- 2026-07-09: Fixed a double-counted repair-cost bug in `scripts/ai_listing_valuation.py`'s profit calculations. `apply_repairs_to_max_bid()` already deducts a repair cost (the high estimate, or mid as fallback) from the recommended max bid to get the bid ceiling. Several downstream profit fields (`economic_profit_mid/worst`, `base_net_profit_mid/worst`, `max_bid_mid/worst_profit`, `net_profit_mid/worst`) were then subtracting `repair_cost_val` (the plain mid estimate) a second time on top of that already-adjusted bid, which is a different number from what was actually deducted -- so profit drifted upward as repair severity increased instead of staying flat, backwards of the intended behaviour. Added `repair_deduction_for_bid`, computed to exactly mirror `apply_repairs_to_max_bid()`'s own high-then-mid fallback, and switched those profit fields to subtract that instead of `repair_cost_val`. Net effect, per explicit user choice ("stay protected"): profit at the recommended max bid now stays roughly constant regardless of repair severity, since the bid itself already dropped to cover it, instead of counter-intuitively rising with repair cost. No repair-pricing thresholds, comps logic, or ML features changed in this pass.
